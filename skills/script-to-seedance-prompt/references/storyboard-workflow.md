# Storyboard Workflow

只在用户提供或明确指定 storyboard 文件时读取本文件。所有导演分镜、粗略镜头说明、镜头表和同类文档统一称为
**storyboard 文件**。

router 已先读取完整剧本。读取用户指定的 storyboard 后，按地点、人物、动作和事件顺序把内容匹配回剧本，
不依赖镜号相同。若中文出现乱码，先在内存中恢复正确文字再解释；未经用户要求，不改写源文件。storyboard
只补充实际视频如何呈现；与剧本冲突时以剧本为准。

## 提取范围

保留所有会改变观众实际看到或听到内容的信息：

- 画面中发生的动作、反应与环境变化。
- 人物和物件的位置、方向、距离、遮挡、进出画与空间关系。
- 景别、机位、角度、构图、镜头运动、跟随对象、焦点变化和可见的镜头震动。
- 剪辑点、转场、动作衔接、揭示方式和镜头结束状态。
- 实际光源、照射方向、颜色、范围、遮挡、移动与开关变化。
- 环境声、动作声、机械声、画外声和与画面同步的声音事件。
- 能落实成可见身体动作、表情、姿势或节奏的表演说明。

忽略不会改变成片画面或声音的信息：

- 剧情目的、观众读取、主题解释和导演意图说明。
- 参考作品分析、参考图编号、ADOPT/ADAPT 说明和素材来源。
- 资产生产、生成平台、交付流程和技术管理说明。
- QA 结论、检查记录、版本说明和行政信息。
- 世界观或设计说明中与当前镜头不可见、不可听的内容。
- 对剧本或其他字段的重复复述。

## 有效解释

- 不按字段机械复制。先理解某条说明最终会让画面或声音发生什么，再用简洁、可执行的中文重写。
- 不把 storyboard 的剧情复述重复塞进 prompt；只补入剧本本身没有表达清楚的实际视频信息。
- storyboard 明确给出景别、机位、运镜、焦点、剪辑或反应镜头时，以该指令覆盖 prompt format 的默认
  摄影倾向；未明确时才根据当前动作、空间和戏剧节拍推导，不套用泛化的场景类型模板。
- 把全段剪辑节奏和常用景别浓缩进【镜头描述】。
- 把具体动作、位置、运镜、焦点、剪辑点和所有灯光信息按发生顺序自然融入【视频内容】。
- 【视频内容】内部不创建"镜头"、"灯光"、"站位"或其他小标题。
- 把有效声音信息压缩进【音效】，只保留声音本身，不复述产生声音的视觉动作。
- storyboard 内容过多时优先保留能明确动作、空间、摄影、灯光、声音和连续性的内容，删除解释性重复。

## 合并检查

- storyboard 没有新增、删除、重排或改写剧本事件。
- 每条保留信息都能回答"观众会看到什么、听到什么，或摄影机如何记录它"。
- 同一信息只出现一次，并处在最适合执行的位置。
- 相邻片段的位置、动作方向、灯光状态、声音延续和镜头结束状态能够衔接。
