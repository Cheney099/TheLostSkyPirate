# Prompt Format

把已完成 segment mapping 的一集定稿剧本变成**可直接投给 Seedance 2.0 的成品视频 prompt**。每个
mapping 条目写成一条独立 prompt，最后按顺序合进同一个交付文件。mapping 只规定边界；写作时仍须读取
对应的剧本原文和 storyboard 原文（若有）。

## Output

一集 → 一个 `prompts/v{YYYYMMDD-HHMM}/EPxx.md`：顶部一行 `# EPxx · Title`，其下按顺序排本集全部
成品段（每段一个 `## EPxx-NN` 块）——**只有成品段，不夹带任何切片清单、词数统计、戏核笔记或流程注释**。
不创建 `EPxx-NN.md` 单段文件。用户只要求新增或修改某段时，在指定的完整集文件中更新对应段块；未指定文件
时使用最新版本，其他段块原样保留。完整集文件尚不存在时，先生成完整集。

每段的固定顺序（一件不许少、一件不许换位）：

```
## EPxx-NN（~Ns）

【资产】

【氛围与画质】

【镜头描述】

【本段大纲】

【视频内容】

【音效】

负面约束：…（固定行）
```

标题一律不带数字（不写 ①②③④）。场景 slug（`EXT. … · DAY`）不出现在段内。

**段头 `## EPxx-NN（~Ns）`**是固定机读格式，**永远显式写、永不省略**：

- **`~Ns`** —— 本段在 `segment_mapping/EPxx.md` 中确定的视频时长（秒，≤15）。

段头不写画幅或地点；地点由【资产】块的场景条目承担。

## Guidelines

### 先看懂资产（写作之前）

若项目提供资产注册表或设计图，先看图并理解人物、道具和场景的稳定外观——服装、体态、结构与空间布局；
把这份理解带进后续写作。没有资产资料时，只使用剧本和 storyboard 能支持的通用描述，不补造资产 id。

### 【资产】

分两步做：**先扫描本段出现的所有资产**——角色、群众、场景、道具、特效，一个不漏；若注册表存在，
再逐个查找并按"平名 → id"绑定。注册表不存在或其中没有对应资产时，按下文纯文字规则处理。

**唯一例外——特效（VFX）永不做 id 绑定**：VFX 照样扫、照样列进【资产】，但**只写文字描述、绝不带
`<asset>` tag**（详见下文"特效"条）。**交付文本里任何一个 `<asset>VFX-…</asset>` 都是错误**——
`<asset>` tag 只允许套在 `Char-` / `Crowd-` / `Scene-` / `Prop-` 上，`VFX-` 永远不套。

**"出现"＝此刻在场，不是"本段剧本行里被点名"。** 从场景开场起滚动维护一份**在场名单**：进了场的
角色/群众，**以及占着画面的大道具/载具**（停在路中的汽车、瘫在地上的名驹），直到剧本明确写离场
（走出画、被抬走、开走）之前，**每一段都算在场**——哪怕剧本这几行没再提。躲到看不见处的除外
（藏进车厢里、掩到门后的人，露面那一段再回名单）。
早先被打倒的对手瘫在地上、退到背景的围观者，都仍在场：照列进【资产】，**让【视频内容】可以引用**——
正文总要给反应镜头，这些在场者自然用得上；具体怎么用，留给写【视频内容】时自己做艺术判断。

条目精瘦——外观以基图为准，**不重述长相、不重复每段当前状态**：

- **角色**：一条角色条目固定只给**通用且跨场景稳定的信息**，通常为嗓音和身高：

  `名字：<asset>id</asset> 嗓音：<gender>，<pitch>，<timbre>，<accent>。身高 Xcm。`

  - 注册表存在时，**嗓音**＝`attributes.voice` 的四个字段 **gender、pitch、timbre、accent，按此顺序原文照搬、
    用逗号连成一句**——不浓缩、不改写、不自由发挥。唯一的清理：字段文本里若混进引号样句/口头禅/台词规则
    （`"Bless your heart."` 之类），剥掉——台词只出现在【视频内容】。
  - 注册表存在时，**身高**＝`attributes.height` 照搬。没有可靠字段时不猜测。
  - 只有当某项特征不依赖当前剧情、无法由基图稳定表达、并且会持续影响生成结果时，才补一条简短的通用说明。
    不把用户给出的具体例子提升成所有同类资产都要遵守的普遍规则。
  - **禁止写当前态**：本段开场时的姿势、持物、伤病变化、情绪、位置、正在进行的动作和残留效果全部写进
    【视频内容】，不在【资产】逐段重复。
- **Crowd（群众资产）**：`群众名：<asset>Crowd-…</asset> 一句话说明是谁。` 无嗓音无身高。散装路人、
  摊贩、打手一律用对应 Crowd 资产盖住。
- **道具 / 场景**：`名字：<asset>id</asset> 一句话说明是什么。` 只有确实跨场景稳定的结构、尺度或行为才写入；
  本段特有的位置、状态变化和动作放进【视频内容】。
- **特效（VFX）——永远纯文字，绝不引用 `<asset>` tag**：特效参考图实测会拖垮生成效果，所以 VFX
  一律只用文字描述、不上任何参考图。条目写法＝`名字：一句话描述这个特效长什么样、怎么动。`（无
  `<asset>`）。注册表里若有 `VFX-…` id，只当"该特效标准长相"读取、把外观翻成简洁中文描述——
  **绝不把它写进 `<asset>` tag**。平名要起得正文里叫得顺口、全集逐字复用（见【视频内容】规矩 7）。
  因为 VFX 从不占 `<asset>` 名额，它**不参与下面的 6 个上限计数**。
- 每段必须且只能有一个场景条目。注册表有对应场景时绑定一个 `Scene-…` id；没有时使用一个不带
  `<asset>` tag 的稳定文字场景描述。CONTINUOUS 续段也不省略场景条目。
- **注册表里没有、但对本集剧本重要的资产**（人物、道具、场景都算）：**一律照样列进【资产】**，
  条目写法跟别的资产一样——只是没有 `<asset>` 引用，改用一段通用基本描述（外观/是什么）顶上：
  `名字：通用基本描述。`
  外观可以**根据本集上下文适当发明**；但必须**保证同一资产在这一整集的每一段里，发明出来的外观
  一字不差、完全一致**——第一次写定后，后续段落照抄那段描述，不许改样、不许换说法。
  本段当前状态、位置和动作另写进【视频内容】。
  **绝不发明 id**、绝不给它编 `<asset>` tag。纯背景闲人则交给 Crowd 资产或干脆不列。
  本段没出现的资产不许列。
- **`<asset>` 引用上限＝每段 6 个**（只数带 `<asset>` 的条目＝场景/角色/群众/道具；**VFX 从不带 tag、
  不计入**）。超过 6 个时，按此优先级保留引用：
  **场景 ＞ 关键人物 ＞ 次要道具 ＞ 次要人物**——从优先级最低的开始往下摘，直到引用数 ≤6。
  被摘掉引用的资产仍保留条目和剧本要求的画面内容，只去掉 `<asset>` tag，改用稳定文字描述。引用上限
  绝不能成为删除人物、动作、道具或剧情事件的理由。

### 【氛围与画质】

每段逐字使用以下恒定内容，永不跳过或单段改写：

电影写实质感，高饱和的糖果色调，华丽考究；暗部靠深色与明暗对比压出层次，绝不发灰、绝不掉饱和；材质对比丰富、细节精致。ARRI Alexa 电影摄影机拍摄的单帧，带轻微胶片颗粒；工业光魔级大片特效。

### 【镜头描述】

**独立成块，只写剪切节奏 ＋ 常用景别**，一两短句带过：

- ✅ `快切，特写和近景为主。`
- ✅ `紧凑快切；紧带特写 / 过肩为主，适当远景和中景。`
- ✅ `紧带特写为主，远景穿插。`
- ✅ `机甲落地时快速跟随下压，冲击结束后固定仰视。`

**怎么判**：storyboard 的明确摄影指令优先，其次是剧本内嵌指令；两者都没有时，再根据本段实际动作、
情绪和空间变化推导。下表只是起点，不是按类型套用的固定模板：

| 本段剧情 | 剪切节奏 | 常用景别 |
|---|---|---|
| 对话 / 文戏 / 情绪戏 | 紧凑快切 | 特写、过肩 |
| 打斗 / 追逐 / 动作戏 | 快切 | 中近景为主，全景读地形、特写给冲击 |
| 氛围 / 独处 / 赶路 | 中快切 | 远景和中景为主，特写点缀 |
| 特效 / 机械启动 / 大场面 | 按实际事件决定：冲击、追逐可加速；揭示、变形、持续奇观可停留 | 全景读尺度，中近景读过程，特写强调关键启动或反应 |

**不写**情绪基调、相机气质描写（"焦急的镜头 / 危急转喜剧 / 相机克制轻推"这类一律不要），也不写
逐镜切换、走位、具体机位——镜头词只允许在【视频内容】里少量点睛。唯一的补充：若本段有**全段性标点**
（升格慢镜进场 / 定格收尾 / 切黑），在这里补一句点明进/出的时刻
（例：`机甲落地瞬间短暂升格，双脚压裂地面后硬切回真实速度。`）。

### 【本段大纲】

一句话戏核：**谁＋最基本的活动**，说清楚本段发生了什么事，
白描到底。不写演法、不写镜头、不写比喻。
例：`John 抱着 Jim 躲避 Dreadnought 的搜索。`

### 【视频内容】

在这里发挥你的导演功力：把给定的剧本片段扩写成**一看就能理解屏幕上正在发生什么**的内容。
大致剧情走向不能变；在此之外，自由运用你对场景图、人物图的理解来设计这个片段。要求写得细致到位、
符合时间顺序和逻辑，让人看一眼就充分理解每一个时刻屏幕上发生什么。

**自然段。** 正文只写连续的自然语言，不设"镜头"、"灯光"、"站位"或其他内部小标题。按相连的戏剧节拍
分成少量自然段，通常 2–4 段；不要一镜一段，也不要为了分段拆散同一连续动作。

**开场状态与调度。** 本段开场时每个人物和关键物件的可见状态全部在这里交代，包括姿势、持物、伤病变化、
残留效果、站位、朝向、距离、遮挡与前后景关系；随后写清楚人物往哪走、手在做什么、两人之间隔着什么。
"John 抱着 Jim 蹲在燃烧残骸后，Dreadnought 落在街道另一端"胜过"John 和 Jim 躲着"。
同一场景的相邻分段之间必须连续：上一段结束在哪里、保持什么状态，下一段就从那里和那个状态开始；
所有移动与状态变化都在正文中交代。

**节奏。** 读出戏剧结构。告白戏 → 留白、长镜头、静默的节拍。动作戏 → 压缩、短切。
揭示要落在一个持续的特写上。

**摄影与灯光。** 具体机位、运镜、焦点、剪辑点以及本段所有实际灯光信息都按发生时机自然嵌入正文。
写清光源、方向、范围、遮挡、移动与开关变化如何作用于画面；不要另建灯光块，也不要把本段灯光塞进
【氛围与画质】。若提供了 storyboard 文件，按 [storyboard-workflow.md](storyboard-workflow.md)
提取、解释并融入有效信息，不机械照抄 storyboard 字段。

**表演。** 把情绪翻译成具体的镜头内指令：
- ❌ "她看起来很伤心" → ✅ "她的目光垂向桌面，下颌绷紧，回答前咽了一下"
- ❌ "他很愤怒" → ✅ "攥着玻璃杯的指节发白，呼吸变短，目光死死盯着她"

默认克制——多数时候一句耳语比嘶吼更有戏。

**按可执行节拍覆盖时长。** 按时间顺序写清实际发生的动作、反应和摄影变化；节拍数量与长度由本段内容和
storyboard 决定，不强制凑成固定数量。每个重要节拍尽量交代**主动作**、必要的**身体细节**和与动作直接
相关的**环境反馈**，但不得为了填满时长添加原始来源没有支持的新事件或无意义反应。

**来源内容不得删除。** 若 mapping 范围无法在 15 秒、台词上限或其他格式约束内完整表达，先返回
segment mapping 步骤调整完整集边界，再重新写受影响段；不得删改剧本事件、对白或必要人物来迁就格式。

#### 1. 只写看得见、听得到的（最高优先级）

模型响应的是**可以被看见、被度量**的东西，不是情绪词。

把每一个抽象概念翻译成可观察的画面：
- ❌ "紧张的场面" → ✅ "男人僵住，缓缓攥紧拳头，光只从侧面打来，半张脸埋在阴影里"
- ❌ "很酷很电影感的车戏、史诗、飞快" → ✅ "低机位跟拍，与车并行，车全力碾过湿滑弯道，大灯发亮，轮胎甩出水雾，镜头带硬颠簸抖动"

用平实、清晰、指令式的语言写。少而准的词胜过多而虚的词。

生成前，先在脑中以观众视角"看"一遍这条 prompt：一切是否毫无歧义、首帧是否非空、主体在哪里
看向哪里是否明确、光从哪里来。

#### 2. 主语明确：谁对谁干了什么

每一个具体动作都要有具体的执行人做主语：谁干了什么、谁对谁做什么、谁对谁施了魔法，
主语和被动方的名字直接写清楚，少用"他/她"兜底。
- ❌ `每一团黑烟都被躲空、砸进空处。`
- ✅ `Dreadnought 的红色搜索光横扫街道，John 抱着 Jim 压低身体躲到燃烧残骸后。`

#### 3. 台词：拆碎、原文保留

- 台词**原封英文**内嵌引号，长破折号锚定时机：`…把话喊出口——"台词原文"——话音未落，…`。
  引号内的台词永不翻译、永不改写。
- **说话方式用中文写**：剧本对白 cue「…」里的英文递送方式/语气是配音指令，不许丢——但要**翻成中文、
  融进说话前的叙事**（`「low, hurried」`→`声音发紧地压着嗓`），**绝不把英文「…」原样搬进正文**；
  中文腔调写好后，英文标注就完成使命了，不要中英各来一遍。
- **总量硬线：全段台词加起来 ≤30 个英文单词**（含 V.O.）。交付前逐句数词、相加比对 30；
  若 mapping 条目超过上限，返回 segment mapping 步骤调整完整集边界；**绝不删除、改写台词，也不在
  mapping 之外临时挪动内容**。
- **均匀分布**：这 ≤30 个词要摊在整段叙事的各个片段里，不许堆在开头或结尾。
- **长句切分（A–B–A–B 衔接）**：一句过长就拆成几个片段——① A 先把前半句说完 → ② 写 B（或 C）的反应
  → ③ A 接着说 → ④ 再给 B/C 的反应。用这种方式衔接，而不是让 A 一口气说完。（反应怎么写＝规矩 4。）
- **V.O./内心独白**：同样内嵌，锚在身体动作短语上并标注（V.O.）——画面上没有说话的嘴型，身体动作照常
  进行。例：`…John 压紧流血的袖口、抬头看向烟层（V.O.）——"They hunted me..."`。

#### 4. 反应描写：多给

当在场者的反应对当前节拍有叙事价值时，写清具体表情或动作；没有 storyboard 摄影指令时，重要反应默认
可用特写强调。storyboard 明确指定其他景别、持续镜头或不切反应时，以 storyboard 为准。不得机械地在每句
台词后添加反应，也不得为了制造反应改变剧情、人物关系或动作节奏。真正独处时可使用来源支持的道具或手部
动作承接节拍。

#### 5. 情绪＝具体的肌肉与身体动作

- **不写情绪标签**："面露怒色"不要——要写具体的表情肌与身体：`视线钉住、抿嘴、下颌发硬、指节绷紧`，
  `眉头压死瞪圆、掀唇露齿，向前逼近一步`；又气又笑＝`先瞪一下眉心一压，随即嘴角失守、别开脸、扶额吐气`。
- **禁一切颜色词写人物状态/感情**：脸色发红、脸色发青、嘴唇发白、血色尽褪…全禁——**病态的白也不行**
  （"身体不好导致的脸色发白"同样禁）。也禁青筋、白气这类卡通脸。改写成其他可见体征：冷汗、发抖、
  气息发紧、站立不稳。
- **绝对禁「眼睛亮起来 / 眼睛一亮 / 眼睛发光 / 眼里放光」**：引擎会把它渲染成字面发光的眼睛（诡异
  VFX）。要表现来了兴致 / 幸灾乐祸 / 坏笑，改写成眼周与视线的实际动作：`眯起眼睛`、`挑起眉毛`、
  `视线一下钉住目标`、`身子往前凑近一寸`——一律写眼皮 / 眉毛 / 视线怎么动，绝不写眼睛本身"亮/发光"。

#### 6. 字面渲染：禁比喻、只写"是什么"

- 生成引擎按字面渲染，任何"像/如…般/仿佛"都会变成噪声或错误内容。把比喻转成可见结果：
  ❌`笑得像刚赢下全世界` ✅`咧嘴大笑`；❌`眼睛瞪成铜铃` ✅`眼睛瞪到极大、又圆又直`。
  **源剧本里的比喻也要翻译掉**，不是照抄。
- 只写"是什么"，不写"不是什么"——负面排除只存在于固定的负面约束行。

#### 7. Age-blind ＋ 命名（引擎靠名字对参考图）

- **不写年龄词**（boy/girl/young/少年/女孩/年轻/小孩…）——引擎会照字面重新选角、毁掉参考图一致性。
  用角色名、服装、动作指代。（台词引号内的原文除外。）
- **人名/专名保留英文**（John、Jim、Steam City），普通名词用中文（机甲、飞艇、扶栏）。
- **永不用剧情相对称呼**（男主/女主/反派/男二）——prompt 是自包含的，引擎不知道谁是主角。无名角色用
  职能标签（发令员、报号员）。
- **全文禁代词**：正文里凡指到角色/生物，一律写名字，"她/他/它"一个都不许出现——不管是说话主语、
  动作主语还是宾语（`Dreadnought 锁定 John`，不是"它锁定他"）。台词引号内的英文代词（she/he/it）除外。
- **已定义的名字绝不换昵称**：【资产】定义过的角色/生物/道具/特效名，正文每次提到都必须用**原样的
  定义名**（如 `Dreadnought`），绝不写成昵称、绰号、泛称或改述（"巨物""那台机器"）——
  引擎会对不上参考图。台词引号内的昵称（"big fella"）除外——那是角色在说话。
  **特效也要固定平名（但不带 tag）**：VFX 一律纯文字（见【资产】），平名自己定成叙事里能自然复用的
  名词（如【资产】里写 `红色搜索光：Dreadnought 传感器发出的窄束红光。`），然后正文每次都逐字
  写`红色搜索光`，不许一会儿"红光"一会儿"扫描光效"。

#### 8. Antislop（禁词）

- EN: breathtaking, stunning, captivating, mesmerizing, masterfully, meticulously, cinematic
  masterpiece, visual feast, a symphony of, seamlessly, effortlessly, elevate, unleash, a testament to
- ZH: 令人叹为观止、令人惊叹、精心打造、匠心独运、视觉盛宴、光影交响、完美呈现、极致体验、引人入胜、
  震撼人心、巧妙融合

### 【音效】

独立小块，`【音效】` 标签后用**一行精瘦列出声音**：环境声、动作声、机械声、画外声、口气声（倒抽凉气、
吞咽、不以为然的语气）。只写听得到的声音，不解释画面、不复述动作，也不含任何台词文字——台词都在
【视频内容】里。
例：`烈火燃烧、重型螺旋桨轰鸣、机甲落地重击、齿轮摩擦。`

### 负面约束（固定行）

每段最后一行，**逐字节照抄**（「负面约束：」标签是交付文本的一部分，不增不减）：

## 检查（交付前，把上面标注过的点从头到尾过一遍）

写完整集后，按下列清单逐段自查；查出问题回去改，改完再查一遍被改的段。

**结构与段头**
- 每段六块＋负面约束行**一件不少、顺序不换**；标题不带 ①②③④；段内无场景 slug。
- 段号、顺序和 `~Ns` 与 `segment_mapping/EPxx.md` 完全一致，且每段 ≤15 秒。
- 交付文件里**只有成品段**——无切片清单、词数统计、流程注释。

**范围与来源**
- 每条 prompt 只覆盖其 mapping 条目指定的范围，不擅自重新切片、合并相邻条目或移动边界。
- 每条 prompt 已回到对应剧本和 storyboard 原文取材，没有只根据 mapping 摘要扩写。
- 没有添加剧本或 storyboard 中不存在的独立建立镜头、动作、对白或过场。

**【资产】**
- 在场名单全覆盖：进场未离场的角色/群众/大道具每段都列；本段没出现的一个不列。
- 每段恰好一个场景条目；注册表有对应场景时绑定一个 `Scene-…` id，没有时使用稳定文字描述。
- 注册表存在时，所有 `<asset>` id 都真实存在、variant 与此刻剧情状态相符；**没有发明的 id**。
- 角色条目只保留嗓音、身高和确有必要的通用稳定说明；没有当前姿势、持物、伤病变化、情绪、位置、动作或残留效果。
- 注册表没有的资产：无 `<asset>` tag、用基本描述顶上，且**整集每一段的描述一字不差**。
- **VFX 一律纯文字、零 `<asset>` tag**——正文没有任何 `<asset>VFX-…</asset>`；每个 VFX 平名全集逐字一致。
- 每段带 `<asset>` 的条目 ≤6 个（VFX 不计）；超了按"场景＞关键人物＞次要道具＞次要人物"从低到高摘：
  只摘 tag 并保留稳定文字条目，不删除剧本要求的资产或画面内容。

**恒定块**
- 【氛围与画质】与本文件规定的恒定内容逐字一致。
- 负面约束行逐字节等于固定行。

**【镜头描述】【本段大纲】**
- 【镜头描述】只有剪切节奏＋景别（外加全段性标点说明），无情绪基调、无逐镜机位。
- 【本段大纲】一句白描：谁＋干了什么。

**【视频内容】**
- 台词：逐句数词、全段合计 ≤30 英文单词（含 V.O.）；原文一字未改；均匀分布；长句按 A–B–A–B 拆开。
- 每个动作都有具名主语；正文零代词、零昵称/泛称，定义名逐字复用（含特效平名）。
- 重要反应得到具体呈现；无 storyboard 冲突时可默认用特写，但没有机械添加无意义反应。
- 节拍数量和长度符合实际动作、对白与 storyboard 节奏，没有为填满时长补造事件。
- 开场状态、人物与物件位置、空间关系、具体摄影和全部本段灯光均已按发生顺序写入正文，相邻段位置与状态连续。
- 正文按连续戏剧节拍分成少量自然段，内部没有"镜头"、"灯光"、"站位"等小标题，也没有一镜一段。
- 提供 storyboard 文件时，已按 storyboard 工作流解释有效视频信息，且没有用 storyboard 改写剧本事实。
- 无情绪标签、无颜色词写状态、无比喻、无年龄词、无剧情相对称呼、无 Antislop 禁词。
- 口气/语气标注已翻成中文融进叙事，无英文「…」残留。

**【音效】**
- 一行精瘦，只列声音；无视觉描述、动作复述或任何台词文字。
